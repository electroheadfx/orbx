
## Contrat de src/main/migrate-profile.js

Module Node pur : `fs`, `path`, `child_process` uniquement, aucun import Electron. Exporte `migrate(options)` et `internals` (constantes héritées, pour les tests). Toutes les constantes ci-dessous sont les seuls littéraux Orbe/orbe tolérés du module.

```text
OLD_DIR = 'Orbe'                     NEW_DIR = 'Orbx'
OLD_STATE = 'orbe.json'              NEW_STATE = 'orbx.json'
OLD_INTERNAL = 'orbe://app/'         NEW_INTERNAL = 'orbx://app/'
KEY_OLD = { service: 'Orbe Safe Storage', account: 'Orbe Key' }
KEY_NEW = { service: 'Orbx Safe Storage', account: 'Orbx Key' }
REG_LEGACY = ['HKCU\\Software\\Classes\\OrbeHTML',
              'HKCU\\Software\\Clients\\StartMenuInternet\\Orbe']
```

Signature et retour :

```text
migrate({ appData, userData, platform = process.platform,
          execFile = execFileSync, log = console.error } = {})
  -> { migrated: boolean, reason: 'absent' | 'exists' | 'custom-path' |
                            'refused' | 'moved' | 'copy-moved' | 'merged' | 'error' }
```

Déroulé exact :

1. Garde chemins : `appData` et `userData` requis. Si `path.resolve(userData) !== path.resolve(path.join(appData, NEW_DIR))`, retour `custom-path` : la migration n'écrit jamais dans un dossier arbitraire.
2. `oldDir = path.join(appData, OLD_DIR)`. `lstat(oldDir)` : erreur → `absent`. Lien symbolique ou non-dossier → log + `refused`.
3. `lstat(userData)` :
   - erreur ENOENT → déplacement direct : `fs.renameSync(oldDir, userData)` ; en cas d'échec (EXDEV, EPERM, EACCES…) `tmp = userData + '.migration-tmp'`, refus si `tmp` existe, sinon `fs.cpSync(oldDir, tmp, { recursive: true, errorOnExist: true, force: false })` puis `fs.renameSync(tmp, userData)` ; ne jamais supprimer `oldDir` en repli de copie ; retour `moved` / `copy-moved`.
   - existe et n'est pas un vrai dossier → log + `refused`.
   - existe et `hasProfileData(userData)` → log + `exists` ; ne rien toucher, ni l'ancien ni le nouveau.
   - existe sans donnée de profil (Electron a pré-créé le dossier, typiquement avec `GPUPersistentCache`) → fusion non destructive de `oldDir` dans `userData`, retour `merged`.
4. `hasProfileData(dir)` : vrai si `orbx.json`, `orbe.json`, `history.json`, `passwords.json`, `Cookies`, `Local Storage`, `Partitions`, `Network`, `Extensions`, `easels` ou `Telechargements` existe comme fichier/dossier réel (pas un symlink). Les artefacts de démarrage seuls (`GPUPersistentCache`, caches, `Preferences`, `Local State` créés tôt par Chromium) ne comptent pas.
5. Fusion non destructive (`merged`) : traiter d'abord `orbe.json` / `orbe.json.bak` → `orbx.json` / `orbx.json.bak` si la cible n'existe pas (fichiers réguliers, pas symlinks). Puis, pour chaque entrée de `oldDir` (`readdirSync().sort()`) : `src=oldDir/name`, `dst=userData/name` ; symlink → laisser (jamais suivi) ; `dst` absent → `renameSync(src, dst)`, ou repli `cpSync(src, dst, { recursive: true, errorOnExist: true, force: false })` sans supprimer `src` ; `dst` existe et les deux sont de vrais dossiers → récursion ; collision fichier/dossier → garder `dst`, laisser `src`. Après la fusion, traiter `<userData>/Partitions` (renommer `orbe`/`orbe-*` → `orbx`/`orbx-*` si la cible n'existe pas). Si `oldDir` est vide, `rmdirSync(oldDir)` ; sinon le laisser (aucune suppression récursive). Les démarrages suivants voient `hasProfileData(userData)` et retournent `exists`.
6. Dans `userData`, renommer `OLD_STATE` → `NEW_STATE` et `OLD_STATE + '.bak'` → `NEW_STATE + '.bak'` seulement si la source est un fichier régulier (`lstat`, pas de symlink) et si la cible n'existe pas.
7. Réécriture JSON pour `[NEW_STATE, NEW_STATE + '.bak', 'history.json', 'history.json.bak']` : si le fichier existe, est régulier et non symlink, `JSON.parse` (échec → laisser le fichier octet pour octet, log). Parcourir récursivement objets et tableaux ; pour chaque chaîne et chaque clé d'objet, remplacer uniquement :
   - une chaîne qui commence par `OLD_INTERNAL` → `NEW_INTERNAL` + reste ;
   - une chaîne égale à `oldDir` ou qui commence par `oldDir + path.sep` → `userData` + reste.
   Si au moins une valeur change : écrire `JSON.stringify(data)` dans `<fichier>.tmp-<pid>` avec le mode d'origine (`stat.mode & 0o777`, 0o600 par défaut), `fsync`, puis `renameSync`. Toute erreur → log + continuer.
8. Partitions : `path.join(userData, 'Partitions')` ; `readdirSync`. Pour chaque nom égal à `orbe` ou commençant par `orbe-`, si l'entrée est un vrai dossier (lstat, pas symlink) et si `orbx` + reste n'existe pas → `renameSync` vers `orbx` + reste. Cette étape couvre aussi bien un déplacement direct qu'une fusion.
9. macOS, seulement si l'étape 3 a déplacé ou fusionné : lire l'ancienne clé avec `execFile('/usr/bin/security', ['find-generic-password', '-s', KEY_OLD.service, '-a', KEY_OLD.account, '-w'], { encoding: 'utf8', stdio: ['ignore', 'pipe', 'ignore'], timeout: 60000 })`. Échec → log `[orbx] migration trousseau` (message seul, jamais le secret), continuer. Vérifier que la nouvelle n'existe pas (`find-generic-password` sans `-w`, `stdio: 'ignore'`) ; si elle existe → ne rien écrire. Sinon `execFile('/usr/bin/security', ['add-generic-password', '-s', KEY_NEW.service, '-a', KEY_NEW.account, '-w', secret], { stdio: 'ignore', timeout: 60000 })` avec `secret = sortie.trim()`. Le délai laisse le temps de répondre aux invites macOS du trousseau. Jamais de shell, jamais le secret dans un log, jamais sur disque, jamais fatal. Risque résiduel assumé et documenté dans le modèle de menace : le secret transite brièvement dans l'argv de `security`.
10. Windows, seulement si l'étape 3 a déplacé ou fusionné : `regExe = path.join(process.env.SystemRoot || 'C:\\Windows', 'System32', 'reg.exe')`. Pour chaque clé de `REG_LEGACY` : `execFile(regExe, ['delete', clé, '/f'], { stdio: 'ignore', timeout: 5000, windowsHide: true })`, erreurs ignorées. Puis `execFile(regExe, ['delete', 'HKCU\\Software\\RegisteredApplications', '/v', 'Orbe', '/f'], ...)`, et les deux valeurs `OrbeHTML` de `HKCU\\Software\\Classes\\.htm\\OpenWithProgids` et `.html\\OpenWithProgids` (`['delete', clé, '/v', 'OrbeHTML', '/f']`). Cinq commandes fixes au total, aucune autre clé, aucun fichier .reg temporaire.
11. Tout le corps dans un `try/catch` : log `[orbx] migration du profil` + message (jamais le secret), retour `{ migrated: false, reason: 'error' }`. `migrate` ne lève jamais.

Coût au démarrage : deux `lstat` quand `Orbx` existe déjà ; aucun minuteur ; aucun accès au trousseau après la première migration.
